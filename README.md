# LedgerFlow — Financial Transaction & Reconciliation API

LedgerFlow is a RESTful financial ledger API built with FastAPI and PostgreSQL. It demonstrates backend engineering concepts used in financial applications, including JWT authentication, account ownership, precise monetary calculations, internal transfers, double-entry ledger records, idempotency, and reconciliation.

**This project uses simulated funds only. It does not process real payments or connect to banking services.**

## Features

- **Authentication:** User registration, Argon2 password hashing, JWT access tokens, and authenticated endpoints.
- **Account management:** Create, list, and retrieve accounts with ownership enforcement.
- **Simulated opening funding:** Record an initial credit in the ledger.
- **Internal transfers:** Transfer funds between eligible accounts owned by the same user.
- **Financial precision:** Use Python `Decimal` and PostgreSQL `NUMERIC(19, 4)` for monetary amounts.
- **Double-entry ledger:** Record a debit for the source account and a matching credit for the destination account.
- **Idempotency:** Reuse an idempotency key to avoid intentionally repeating the same transfer.
- **Balance calculation:** Calculate account balances from ledger entries rather than maintaining a freely editable balance.
- **Transaction integrity:** Use database transactions and account-row locking during transfers.
- **Ledger history:** Retrieve ledger entries with pagination and optional account filtering.
- **Reconciliation:** Check transfer records for missing, unbalanced, or inconsistent ledger entries.
- **API documentation:** Interactive Swagger UI generated by FastAPI.
- **Database migrations:** Manage schema changes using Alembic.
- **Automated checks:** Pytest tests and a GitHub Actions CI workflow.

## Core Financial Rules

### Double-entry bookkeeping

A successful internal transfer creates two ledger entries:

1. A debit against the source account.
2. An equal credit to the destination account.

For a transfer of USD 125.5000:

| Entry | Amount |
|---|---:|
| Source account debit | 125.5000 |
| Destination account credit | 125.5000 |
| Net ledger movement | 0.0000 |

### Balance calculation

The balance is calculated as:

`Total credits - Total debits`

Opening funding is recorded as a credit. Internal transfers debit one account and credit another.

### Transfer validation

The API checks account ownership, account status, matching currencies, positive transfer amounts, and sufficient funds. Transfers are committed as a database transaction so their records can be rolled back together on failure.

### Idempotency

Transfers accept an `Idempotency-Key` request header. A repeated request with the same key and matching transfer details returns the existing transfer rather than intentionally creating another one.

### Reconciliation

The reconciliation endpoint checks completed transfer records against their associated ledger entries, including entry counts, debit and credit totals, transfer amounts, and currencies.

## API Endpoints

All application endpoints use the `/api/v1` prefix except `/health`.

### Health

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/health` | Check API and database connectivity |

### Authentication

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/api/v1/auth/register` | Register a user |
| POST | `/api/v1/auth/login` | Obtain a JWT access token |
| GET | `/api/v1/auth/me` | Retrieve the authenticated user's details |

### Accounts

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/api/v1/accounts` | Create an account |
| GET | `/api/v1/accounts` | List the current user's accounts |
| GET | `/api/v1/accounts/{account_id}` | Retrieve an owned account |
| POST | `/api/v1/accounts/{account_id}/fund` | Record simulated opening funding |
| GET | `/api/v1/accounts/{account_id}/balance` | Calculate the account balance |

### Transfers

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/api/v1/transfers` | Execute an internal transfer |

Transfers require authentication and an `Idempotency-Key` header.

### Ledger and reconciliation

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/v1/ledger/entries` | Retrieve ledger entries |
| GET | `/api/v1/ledger/reconcile` | Check transfer-to-ledger consistency |

Ledger history supports an optional `account_id`, `limit` and `offset`.

## Database Models

- **User:** Identity, email, password hash, role, and account status.
- **Account:** Owner, account name, currency, status, and opening-funding state.
- **Transfer:** Source and destination accounts, owner, amount, currency, status, and idempotency key.
- **LedgerEntry:** Account, optional transfer reference, debit or credit type, amount, currency, and timestamp.
- **Alembic version table:** Tracks applied database migrations.

PostgreSQL constraints enforce important data rules, including positive transfer and ledger amounts, valid currency formats, valid ledger entry types, distinct transfer accounts, and unique owner/idempotency-key combinations.

## Local Setup — Windows PowerShell

### 1. Clone the repository

Replace the URL with your actual public GitHub repository URL.

```powershell
git clone https://github.com/YOUR_GITHUB_USERNAME/ledgerflow-financial-transaction-api.git
cd ledgerflow-financial-transaction-api
```

### 2. Create and activate a virtual environment

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 3. Install dependencies

```powershell
python -m pip install -r requirements.txt
```

### 4. Configure environment variables

Create a local `.env` file using `.env.example` as a reference.

Configure the following values for your local PostgreSQL database:

```dotenv
DATABASE_URL=postgresql+psycopg://ledgerflow_app:YOUR_DATABASE_PASSWORD@localhost:5432/ledgerflow_db
SECRET_KEY=YOUR_LONG_RANDOM_SECRET
ACCESS_TOKEN_EXPIRE_MINUTES=30
ENVIRONMENT=development
```

Use your own database credentials and a securely generated secret key. Never commit `.env` or expose production secrets.

### 5. Apply database migrations

```powershell
alembic upgrade head
```

### 6. Start the API

```powershell
uvicorn app.main:app --reload --reload-dir app
```

### 7. Open the documentation

- Swagger UI: http://127.0.0.1:8000/docs
- ReDoc: http://127.0.0.1:8000/redoc
- Health check: http://127.0.0.1:8000/health

Register a user, log in, authorize Swagger using the returned bearer token, and then test the account and ledger endpoints.

## Testing

Run the automated tests:

```powershell
python -m pytest -q
```

Run code-quality checks:

```powershell
python -m ruff check app tests
```

Check migration status:

```powershell
alembic current
alembic heads
```

The initial automated tests validate request schemas and monetary input constraints. The API's registration, authentication, account, funding, transfer, balance, and reconciliation workflows should also be verified against a test database.

Important additional tests for a financial application include:

- Insufficient-funds rejection.
- Cross-user access prevention.
- Repeated and conflicting idempotency keys.
- Concurrent transfers from the same account.
- Transaction rollback on database errors.
- Matching debit and credit entries.
- Reconciliation of intentionally corrupted test records.

## Continuous Integration

The GitHub Actions workflow is located at `.github/workflows/ci.yml`. It provisions PostgreSQL, installs dependencies, and runs automated checks on pushes and pull requests.

Review the workflow results after pushing the repository. A successful local run does not automatically prove that the CI environment or deployment is working.

## Security and Scope

LedgerFlow is a portfolio project, not a production banking system.

- Funding is simulated and must not be interpreted as a real deposit.
- The API does not integrate with payment networks or financial institutions.
- Production deployment would require further security review, operational monitoring, backup and recovery procedures, stronger audit controls, and comprehensive integration and concurrency testing.
- Do not use real financial data or production credentials in this demonstration.
